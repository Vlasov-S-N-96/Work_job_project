5. Тестовые данные для оплаты

Необходимо применить технику тест-дизайна "Таблица принятия решений". В нашем приложении есть модуль, включающий оплату через Paypal.

У аккаунта Paypal есть три статуса: valid, invalid и blocked, а также такая характеристика, как доступный баланс, который может быть нулевым и положительным (= достаточным для оплаты).

В случае, если статус карты valid, а баланс на аккаунте достаточный для покупки, пользователь может совершить покупку. Во всех остальных случаях транзакция будет отклонена.

  • Создать таблицу, которая будет учитывать эти условия и выводить действие, согласно им.

9. Сниффер (настольный компьютер)

Выполнить в программе Proxyman.

https://intern.demoshopping.ru

  • 1. Изменение количества товаров в корзине. В запросе отправляется "2 товара", а вы должны вернуть "500".
  • 2. Подмена статус-кода. Смоделируйте ситуацию, при которой при обращении к https://intern.demoshopping.ru сервер вернет статус-код 403. Запросы к другим ресурсам должны работать в штатном режиме.
  • 3. Перенаправление запросов (демонстрация). Перенаправьте запрос с https://intern.demoshopping.ru на https://google.com (это не stage-стенд, а просто пример перенаправления на другой хост).

📌 Пример решения (видео/скриншоты)

10. Сниффер (смартфон)

Выполнить в программе Charles Proxy.

  • 1. Подмена удаляемого товара. Добавьте несколько разных товаров в корзину, отправьте запрос на удаление одного из них, но видоизмените его так, чтобы он удалил другой товар.
  • 2. Подмена картинки. Смоделируйте ситуацию, при которой при обращении к https://intern.demoshopping.ru пользователь увидит в браузере любую другую картинку (вместо оригинальной).
  • 3. Скриншот HTTPS-запроса. Приложите скриншот любого перехваченного HTTPS-запроса с вашего мобильного устройства. В заголовке User-Agent должна быть информация о вашем устройстве.

11. Postman: коллекции для SOAP и REST API

📡 SOAP-сервис (страны)

Протокол SOAP. Тестировать запросы можно в Postman

  • WSDL сервиса: http://webservices.oorsprong.org/websamples.countryinfo/CountryInfoService.wso?WSDL
  • Список ISO-кодов стран (для тестирования): Wikipedia: ISO 3166
  • В коллекцию включить методы: ListOfContinentsByName, CountryName, FullCountryInfo, LanguageName.
  • В качестве страны используйте свою родную (Россия, ISO код RU или RUS).

🛒 REST API (интернет-магазин DemoShopping)

Создайте коллекцию "DemoShopping", папки "Products" и "Cart".

  • Swagger документация: https://intern.demoshopping.ru/api-docs/ (все эндпоинты).
  • Тестовые данные для оплаты картами: Kaiten — тестовые карты.
  • В методе PUT для обновления товара удалите из тела запроса id (иначе ошибка).
  • Для запросов к корзине требуется авторизация (метод /users/login).
  • Проверки строить на статус-кодах, названия запросов делать понятными.
  • Создать переменные окружения QA: базовый URL, key (токен), ID товара и т.д. Переменную токена назвать key (для сохранения публичности коллекции).
  • Для всех методов Products написать автотесты: статус-код, тип данных, время ответа, изменение ключей/значений.
  • Перед началом и после работы со Swagger выполнить метод "Сброс базы данных" (очистка).
  • Результат: ссылка на публичную коллекцию Postman (инструкция по публикации).
